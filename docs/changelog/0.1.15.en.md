# Soreno 0.1.15

## What’s new

### Git changes for a whole group

Opening a group’s **Overview** now shows, on the right, the Git state of all its repositories: branch, how far ahead or behind the remote, number of staged, modified and untracked files, and active agents.

- Only repositories with changes are listed, along with the group total. Expand a repository to see its files and their diff.
- Stage, unstage or discard changes file by file, or stage the whole group at once with **Stage all**. Discarding a file or resolving a conflict asks for confirmation.
- **Commit** commits the staged changes of each repository with the same message.
- **Fetch** fetches updates for every repository in the group.
- The panel updates when an agent finishes its turn, when you come back to Soreno, or with **Refresh repositories**. A repository’s icon opens its usual Git panel.

### Fetch always within reach

In a project’s Git panel, **Fetch** is now a separate button next to the sync menu, instead of an entry in that menu. You can use it right away, without waiting for the remotes to be read.

## Changes

- Codex agents in a group can now modify the group’s repositories, asking for your approval as in a regular project. Before, they could only read them.
- The project list shows up as soon as it is loaded, without waiting for every worktree to be read.
- In the Git history, the current branch is shown as `✓ HEAD -> branch`, tags are prefixed with `tag:`, and all rows have the same height.
- The **Merge into \<main branch\> and delete** confirmation now talks about a source branch and a target branch. If there is a conflict, it tells you to resolve it in **Changes** for the source worktree.

## Fixes

- **Merge into \<main branch\> and delete** is safer:
  - merging a conflict resolution keeps the correct history;
  - it works even when commit signature display is enabled in your Git configuration;
  - if the repository changed in the meantime, Soreno asks you to refresh and confirm again;
  - a worktree used by a session of the main project is no longer deleted;
  - an ambiguous `mergeOptions` Git configuration is refused before anything is changed, with a message explaining what to remove.
- The **Branches** view updates after a change made by an agent.
- Deleting a worktree completes even if reloading the project list fails.
- Terminals stay responsive when an SSH session is slow to start or stop.
- Pasting very long text into a terminal is more reliable: it is sent in chunks, without breaking accented or special characters.
- In the status bar of an SSH project, the **Disconnect**/**Connect** and **Ports** buttons are better aligned.
