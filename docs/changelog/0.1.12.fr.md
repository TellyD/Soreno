# Soreno 0.1.12

## Changements

### Un seul endroit pour les erreurs

Les erreurs, validations et avertissements s’affichent désormais tous au même endroit : une notification en bas à droite de la fenêtre, au lieu de messages dispersés dans chaque panneau.

- Les erreurs sont en rouge, les avertissements en ambre ; un même problème répété n’est affiché qu’une fois, avec un compteur.
- Les notifications se ferment seules après quelques secondes ; survoler une notification suspend sa fermeture. Celles qui proposent une action, comme **Réessayer**, restent affichées jusqu’à ce que vous les fermiez.
- Les messages sont toujours rédigés dans la langue de l’interface : les sorties techniques brutes (Git, SSH, Codex…) ne sont plus affichées. C’est aussi le cas des erreurs de l’explorateur de fichiers.

### Connexion SSH guidée

Ajouter un projet SSH est plus simple :

- Renseignez le serveur et le compte, puis cliquez sur **Choisir un dossier…**. Pour un serveur déjà approuvé, ses dossiers s’affichent directement.
- Pour un nouveau serveur, Soreno affiche son empreinte. Comparez-la avec celle fournie par l’administrateur ou la console du serveur, puis confirmez : les dossiers s’ouvrent aussitôt. Si vous annulez, rien n’est mémorisé.
- Si la clé du serveur a changé, Soreno bloque la connexion et ne propose pas de la remplacer automatiquement.
- Si vous choisissez par erreur le fichier `.pub` au lieu de la clé privée, Soreno vous l’explique.
- En cas d’échec, le message indique quoi vérifier : compte, clé privée, réseau ou pare-feu. Si votre clé est protégée par une phrase secrète et qu’elle n’est pas chargée dans l’agent SSH, Soreno vous demande de la charger avec `ssh-add`.
- Les mêmes étapes s’appliquent quand vous ouvrez ou clonez un dépôt sur un serveur SSH.

### Historique des sessions SSH conservé

Rattacher une session SSH, après avoir fermé Soreno ou perdu la connexion, restaure maintenant tout l’historique du terminal, y compris ce que l’agent a affiché pendant l’absence : on peut de nouveau remonter dans une conversation Claude Code, OMP, Pi, Codex ou dans un shell. Le collage de plusieurs lignes et la souris restent actifs après le rattachement. Les sessions déjà lancées avec une version précédente retrouvent ce comportement après leur prochain redémarrage.

### Messages de commit générés plus vite

La génération du message de commit utilise maintenant le mode rapide de Codex et répond plus vite.

### Autres changements

- L’onglet **Explorateur** du panneau latéral s’appelle maintenant **Fichiers**. La branche courante et l’avance ou le retard sur le remote restent visibles quand cet onglet est ouvert.
- Pendant une opération Git (indexer, restaurer…), la liste des fichiers modifiés et le diff restent affichés au lieu de disparaître.
- Ajouter un projet déjà présent dans la liste ne crée plus de doublon : Soreno sélectionne le projet existant.

## Corrections

- L’indicateur d’activité des agents s’arrête désormais quand le CLI cesse de travailler, même si celui-ci ne l’a pas signalé : un tour de Claude Code interrompu avec Échap ou une demande de permission en attente ne le laissent plus tourner indéfiniment.
- La barre d’état n’affiche le coffre et l’état d’enregistrement des notes que dans l’espace **Notes**. Le coffre local porte aussi un nom traduit quand l’interface est en anglais.
- La lecture des changements Git des projets WSL est plus fiable, y compris pour les gros fichiers.
