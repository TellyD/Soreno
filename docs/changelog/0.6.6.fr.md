# Soreno 0.6.6

## Nouveautés

### OMP sans terminal

- **Nouvelle session** > **Chat (OMP)** lance OMP dans une vue de conversation, sans terminal, dans les projets locaux, WSL et SSH. Les réponses s’affichent au fil de l’eau ; chaque outil tient sur une ligne qui se déplie sur sa sortie ou sur le diff d’une modification.
- Les autorisations et les questions d’OMP s’affichent au-dessus de la zone de saisie et se règlent d’un clic, ou au clavier avec **Entrée** et **Échap**. La session est marquée en attente de réponse comme les autres agents.
- La zone de saisie propose le choix du modèle, avec une recherche par nom ou fournisseur, le niveau de raisonnement, l’occupation du contexte, les pièces jointes (images et fichiers texte) et l’arrêt de l’étape en cours.
- La conversation reprend au redémarrage de la session. Les remarques du panneau Git et les commentaires du Kanban transmis à l’agent lui arrivent directement.
- **Reprendre une conversation…**, dans le menu **…**, liste les conversations OMP antérieures du projet, de la plus récente à la plus ancienne, avec une recherche, et ouvre celle choisie à la place de la conversation en cours, comme `/resume` dans OMP.
- Les sous-agents lancés par OMP s’affichent sous l’appel qui les a lancés, avec ce qu’ils font, leurs jetons, leur durée et un bouton pour en arrêter un.
- La liste de tâches d’OMP s’affiche au-dessus de la zone de saisie, avec son avancement et la tâche en cours ; elle se déplie sur chaque phase et l’état de ses tâches.
- OMP doit être installé dans l’environnement du projet ; ses modèles, comptes et autorisations restent ceux de sa configuration.

## Changements

- Le texte en gras ou en italique garde son code et ses liens : un nom de fichier en code dans un passage en gras s’affiche en code gras, sans ses accents graves, dans les conversations, le Kanban et les notes de version.
- Les blocs de code `mermaid` s’affichent en schéma, dessiné par Mermaid aux couleurs du thème clair ou sombre, dans les conversations, le Kanban, l’aperçu des fichiers Markdown et les notes de version. Un schéma large défile horizontalement ; un schéma invalide ou un diagramme de Gantt garde son code.
- Un agent peut créer une issue directement dans Linear quand vous le lui demandez (« ajoute une issue dans Linear »), dans le projet Linear lié au projet de la session. Sinon, l’issue reste locale, sauf si la session travaille déjà sur une issue Linear. Le badge **Linear** des issues est désormais coloré.
- Avec les icônes de fichiers colorées, les modifications Git gardent leurs icônes d’état habituelles ; les icônes colorées ne s’appliquent plus qu’à l’explorateur et à la recherche.
- **Paramètres › Skills** n’affiche plus les projets dont le dossier a disparu.
- Retouches visuelles : cartes de projet sans fond de sélection, champs du dialogue de création d’issue, icône du terminal divisé distincte de celle du panneau Git, icône d’affichage des fichiers Git orientée selon la disposition.

## Corrections

- Sur macOS, la barre d’espace insère de nouveau une vraie espace dans les terminaux, au lieu d’une espace insécable que certains agents ne reconnaissaient pas.
- Dans une session SSH dont le serveur n’est pas en UTF-8, ce qui est courant depuis l’app macOS, Soreno passe le shell en UTF-8 quand le serveur le permet : un prompt accentué ou une longue ligne ne se mélangent plus à l’effacement.
