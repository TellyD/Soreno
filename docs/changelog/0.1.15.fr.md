# Soreno 0.1.15

## Nouveautés

### Changements Git de tout un groupe

Ouvrir la **Vue d’ensemble** d’un groupe affiche maintenant, à droite, l’état Git de tous ses dépôts : branche, avance ou retard sur le remote, nombre de fichiers préparés, modifiés et non suivis, agents actifs.

- Seuls les dépôts qui ont des changements sont listés, avec le total du groupe. Dépliez un dépôt pour voir ses fichiers et leur diff.
- Préparez, retirez ou annulez les changements fichier par fichier, ou préparez tout le groupe d’un coup avec **Tout préparer**. Annuler un fichier ou résoudre un conflit demande une confirmation.
- **Commit** enregistre les changements préparés de chaque dépôt avec le même message.
- **Fetch** récupère les nouveautés de tous les dépôts du groupe.
- Le panneau se met à jour quand un agent termine son tour, quand vous revenez dans Soreno ou avec **Actualiser les dépôts**. L’icône d’un dépôt ouvre son panneau Git habituel.

### Fetch toujours à portée de main

Dans le panneau Git d’un projet, **Fetch** est maintenant un bouton à part, à côté du menu de synchronisation, au lieu d’une entrée de ce menu. Il est utilisable tout de suite, sans attendre la lecture des remotes.

## Changements

- Les agents Codex d’un groupe peuvent maintenant modifier les dépôts du groupe, en demandant votre accord comme dans un projet ordinaire. Auparavant, ils ne pouvaient que les lire.
- La liste des projets s’affiche dès son chargement, sans attendre que tous les worktrees soient lus.
- Dans l’historique Git, la branche courante s’affiche sous la forme `✓ HEAD -> branche`, les tags sont préfixés par `tag:`, et toutes les lignes ont la même hauteur.
- La confirmation de **Fusionner dans \<branche principale\> et supprimer** parle de branche source et de branche cible. En cas de conflit, elle indique de le résoudre dans **Changements** pour le worktree source.

## Corrections

- **Fusionner dans \<branche principale\> et supprimer** est plus sûre :
  - la fusion d’une résolution de conflit garde le bon historique ;
  - elle fonctionne même quand l’affichage des signatures de commits est activé dans votre configuration Git ;
  - si le dépôt a changé entre-temps, Soreno vous demande d’actualiser et de confirmer à nouveau ;
  - un worktree utilisé par une session du projet principal n’est plus supprimé ;
  - une configuration Git `mergeOptions` ambiguë est refusée avant toute modification, avec un message qui explique quoi retirer.
- La vue **Branches** se met à jour après une modification faite par un agent.
- La suppression d’un worktree va jusqu’au bout même si le rechargement de la liste des projets échoue.
- Les terminaux restent réactifs quand une session SSH met du temps à démarrer ou à s’arrêter.
- Coller un très long texte dans un terminal est plus fiable : il est envoyé par morceaux, sans abîmer les caractères accentués ou spéciaux.
- Dans la barre d’état d’un projet SSH, les boutons **Déconnecter**/**Connecter** et **Ports** sont mieux alignés.
