# Soreno 0.5.0

## What’s new

### Local Kanban

The Kanban now works entirely locally: issues, columns, comments, labels, images and links to agents are stored in Soreno, on your computer. The board keeps its look and features: tabs, drag and drop, issue details, agent launch, end-of-task summary and move to review.

- The board starts with the **Soreno** team and the Backlog, Todo, In Progress, In Review, Done and Canceled columns. Issues are numbered `SOR-1`, `SOR-2`…
- An issue’s project is directly a Soreno project, and an agent started from the issue runs in that project: the agent no longer has its own project choice.
- Create a label by typing its name in the label selector.
- In **New issue**, check **Start an agent** then **Create and start agent** to create the issue and start an agent on it right away.
- **New sub-issue**, in an issue’s details, creates a linked sub-issue.
- Linked pull requests are recognized from their links in the description and comments.
- When you ask an agent to add an issue, it is created in the Soreno Kanban, with no prior setup.

### Mobile access without Tailscale

- Mobile access now goes through the Soreno relay: in the **Mobile** dialog, **Enable**, then scan the QR code with the phone’s camera. Sessions open from any network, cellular included, with nothing to install on the phone or on the server besides Soreno, no `sudo` and no port to open.
- Traffic between the phone and the server is end-to-end encrypted: the relay connects them without reading sessions, conversations or images.
- One phone can be paired with several servers: the page shows them all. The dialog lists paired phones, and **Revoke** cuts one off immediately, open conversations included.
- The mobile page can also scan a QR code with the camera, to pair the app added to an iPhone’s home screen.

## Changes

- The Linear connection and its API key are gone, and its issues are not imported: the Kanban starts empty.
- Deleting an issue is permanent, after confirmation.
- Issues no longer have an assignee.
- Mobile access no longer uses Tailscale, and the principal and attached servers are gone. On a server already enabled, **Update** removes the old Tailscale publications and connects it to the relay; phones then need to be paired once.
- In **Settings** > **Skills**, each skill shows whether it can be updated and why not otherwise (local source, npm package, untracked source); the update button no longer appears when an update is impossible.
- On the mobile page, sessions are listed by launch time, newest first.
- In a worktree’s Git panel, the branch no longer appears twice in the header when the project name already contains it.
- On macOS, the window’s title bar follows the light or dark theme chosen in Soreno.
