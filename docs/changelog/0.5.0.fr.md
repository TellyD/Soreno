# Soreno 0.5.0

## Nouveautés

### Kanban local

Le Kanban fonctionne désormais entièrement en local : issues, colonnes, commentaires, labels, images et liens avec les agents sont enregistrés dans Soreno, sur votre ordinateur. Le tableau garde son apparence et ses fonctions : onglets, glisser-déposer, détail de l’issue, lancement d’un agent, résumé de fin de tâche et passage en revue.

- Le tableau démarre avec l’équipe **Soreno** et les colonnes Backlog, Todo, In Progress, In Review, Done et Canceled. Les issues sont numérotées `SOR-1`, `SOR-2`…
- Le projet d’une issue est directement un projet Soreno, et un agent lancé depuis l’issue démarre dans ce projet : il n’y a plus de choix de projet séparé pour l’agent.
- Un label se crée en saisissant son nom dans le sélecteur de labels.
- Dans **Nouvelle issue**, cochez **Lancer un agent** puis **Créer et lancer l’agent** pour créer l’issue et démarrer aussitôt un agent dessus.
- **Nouvelle sous-issue**, dans le détail d’une issue, crée une sous-issue rattachée.
- Les pull requests liées sont reconnues à partir de leurs liens dans la description et les commentaires.
- Quand vous demandez à un agent d’ajouter une issue, elle est créée dans le Kanban de Soreno, sans configuration préalable.

### Accès mobile sans Tailscale

- L’accès mobile passe désormais par le relais Soreno : dans le dialogue **Mobile**, **Activer**, puis scanner le QR code avec l’appareil photo du téléphone. Les sessions s’ouvrent depuis n’importe quel réseau, 4G comprise, sans rien installer sur le téléphone ni sur le serveur en dehors de Soreno, sans `sudo` ni port à ouvrir.
- Les échanges entre le téléphone et le serveur sont chiffrés de bout en bout : le relais met en relation sans lire les sessions, les conversations ni les images.
- Un même téléphone peut être appairé à plusieurs serveurs : la page les affiche tous. Le dialogue liste les téléphones appairés, et **Révoquer** coupe l’un d’eux immédiatement, conversations ouvertes comprises.
- La page mobile peut aussi scanner un QR code avec la caméra, pour appairer l’app ajoutée à l’écran d’accueil d’un iPhone.

## Changements

- La connexion à Linear et sa clé d’API disparaissent, et ses issues ne sont pas importées : le Kanban part vide.
- Supprimer une issue est définitif, après confirmation.
- Les issues n’ont plus de responsable.
- L’accès mobile n’utilise plus Tailscale, et le serveur principal et les serveurs rattachés disparaissent. Sur un serveur déjà activé, **Mettre à jour** retire les anciennes publications Tailscale et le connecte au relais ; les téléphones doivent ensuite être appairés une fois.
- Dans **Réglages** > **Skills**, chaque skill indique s’il peut être mis à jour et pourquoi sinon (source locale, paquet npm, source non suivie) ; le bouton de mise à jour n’apparaît plus quand elle est impossible.
- Sur la page mobile, les sessions sont listées par date de lancement, les plus récentes en premier.
- Dans le panneau Git d’un worktree, la branche n’apparaît plus deux fois dans l’en-tête quand le nom du projet la contient déjà.
- Sur macOS, la barre de titre de la fenêtre suit le thème clair ou sombre choisi dans Soreno.
