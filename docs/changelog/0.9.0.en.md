# Soreno 0.9.0

## What’s new

### Automations

The new **Automations** view in the left bar runs an agent at a set time on an SSH project, for example a skill every morning. It runs on the server through a systemd user timer, even when Soreno is closed and the computer is off.

- An automation combines a name, an SSH project, an agent (Claude Code, Codex, Pi or OMP), a prompt and a schedule: **Every day**, **Weekdays** or **Every week**, at the chosen time. In the prompt, `/` suggests the project’s and the server’s skills, in the agent’s syntax.
- Each automation has its own favorite session in the project. **Open session** attaches to it and replays the agent’s output; the agent stays open at the end of its turn.
- The list shows the schedule, the next and the last run, plus a badge for a run not yet opened, and refreshes while it stays on screen. A run is skipped while the previous run’s session is still open.
- **Run now** starts a run right away. The **Active** switch pauses or resumes the automation immediately. The name, prompt and schedule can still be edited. **Delete automation** removes the timer from the server and keeps the session.

Requires a Linux server running systemd, with `systemctl --user`.

## Changes

- A worktree project removed outside Soreno, for example with `git worktree remove`, disappears from the project list unless it is open.

## Fixes

- On a busy SSH server, a command that times out no longer makes the other SSH commands running on that server fail.
